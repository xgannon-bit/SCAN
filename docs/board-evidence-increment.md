# Board evidence and live processing increment

Continue the existing full-board workspace. The preserved full-board demonstration
uses `.next-full-board` on port 3221. This increment uses
`SCAN_BOARD_EVIDENCE_BUILD=1`, `.next-board-evidence`, and port 3222.
Run `scripts/start-board-evidence.ps1` after building that separate target.
No source archive, candidate or machine program is changed merely by displaying it.

## Review corrections

Candidate CAD/Gerber layers require a fresh preservation proof bound to the exact
original/candidate archive and selected member identities plus the complete repair
request. Only the same supported schema with freshly reproduced ROI X/Y edits,
unchanged module records and unchanged Master qualifies for frame equivalence.
All existing baseline registration checks still apply. Other candidate types stay
held while their literal native records remain visible.

A current failed Gerber fit/check is absent from the normal comparison. An explicit
unregistered diagnostic mode retains its geometry, uses warning colors and cannot
claim passed registration. Stale interpretations/scopes never qualify even in that
mode. Native registration additionally requires the existing exact-source evidence.

Candidate literal read-back and full native preservation have separate labels.
The session reproduces accepted output through the existing guarded worker and
compares the complete main XML hash, Master, assets and literal records. The
stronger proof exists only in runtime state and is invalidated by source, candidate
or request changes. Reopening requires fresh verification; saved events and labels
cannot restore authority. Eagle remains unverified. Combined preparations retain
their separate existing candidate verification route; they do not inherit the
ROI-only frame proof.

## Registration and component processing

The Registration inspector shows existing declared revision/frame evidence, fit
and independent-check residuals, provenance and holds. Supported native control
geometry is plotted on the full board, with explicit unit/Y conversion. These are
footprint-origin controls, not inferred body centers or pad ownership. Qualified
Gerber residuals can be displayed in the same native frame through the already
checked transform chain. Unsupported geometry remains in its original frame.

Analyze on board invokes the real source/native diagnosis worker. Per-component
started, checked and held messages are emitted at actual processing boundaries.
Candidate exports reuse their actual placement/model checks. A strict source,
snapshot, interpretation, module/reference/Part/Master and before-geometry join
controls visual highlighting. New preparations appear only as staged ghosts in
an explicit existing module until candidate read-back. No event establishes
analyzed, accepted, delivered, taught or machine-verified status.

The full scene always comes from native records, never from the event subset.
Transport retains at most 1024 events per run; the saved display journal retains
the last 500 and discloses its limit. Fast work is not slowed down to animate it.
Replay freezes a journal snapshot, leaves the full original board visible and
cannot execute a repair. Historical or incompatible geometry remains held.
Candidate tools minimize during writer checks without unmounting the operation;
the board stays visible while the existing package verification continues.

## Verification and boundaries

Public tests are independently authored synthetic fixtures. They cover positive
frame equivalence; changed modules, source/interpretation drift and missing proof;
failed independent checks; missing history, missing assets and unobserved XML byte
changes; original/proposed review and candidate export; fresh project reopening;
worker event provenance; bounded transport; and non-mutating full-board replay.
Private actual-source checks and screenshots are retained outside Git.

Actual registration still needs revision-matched artwork evidence, physical
side/module and coordinate/anchor conventions, and corresponding fit/check
features. Numeric overlap does not establish these facts. Native binding semantics,
FOV coverage and Eagle open/save/reopen behavior need separate controlled evidence.
This increment does not create new repair rules, enable inspections or grant release.
