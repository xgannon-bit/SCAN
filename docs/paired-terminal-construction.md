# Disabled paired-terminal construction

This reusable constructor prepares a previously missing job-local placement,
Master and three reference windows: a manufacturer body and two source-owned
terminal lands. There are no board reference lists or manufacturer dimensions
in the constructor. R02 is a structural reference only, not geometry or teaching
authority. Exact native template reuse remains a separate route.

## Evidence and bounds

Load a reviewed JSON profile under Repair Review → Package construction evidence.
It binds literal source pattern, graphics, component-definition and attached-pattern
alias identities, matched native CAD part names, a manufacturer drawing URL/hash/page
and match explanation, body/electrode dimensions, explicit pad-to-pin mapping and
the original native field-format seeds. Keep private profiles in saved projects,
outside the public repository. The drawing match/dimensions are reviewed inputs,
not automatic datasheet recognition. The writer never fetches remote sources.

The source reader must establish two congruent, rectangular, cardinal, explicit
zero-hole top-layer lands owned by the unique placement. Numeric pad/pin mappings
must close on the actual linked component definition and declared pad count. A
literal attached-pattern alias is an explicit reviewed crosswalk; no name-similarity
heuristic establishes that alias. The manufacturer electrode projections must
overlap the owned lands by the profile's conservative minimum fraction. The owned
pair axis/midpoint plus explicit drawing offsets establish the nominal body anchor.
Silkscreen markings and recommended lands are not substituted for body or owned
terminal geometry. A terminal land window is not a taught solder/lead window.

The first supported native-frame hypothesis uses source mm at 1:1 native literal
scale, a common translation witnessed by at least four other noncollinear CAD
correspondences, inverse source/native cardinal angle literals, source-pattern axes
for local terminal geometry and an explicit new body origin. No mirror, noncardinal
rotation, side ambiguity qualification or inferred native pad mapping is written.
These witnesses support an offline trial; they do not qualify Eagle interpretation.

Native seeds must pass the bounded neutral field contract and exact placement/Master
identity checks. Body Mount and terminal Solder rectangular window formats cannot
contain opaque learned window data. Only new records are appended. New placement
and window ENABLE fields remain false. Algorithms, bindings, FOV lists, shared
library category links and learned model state are absent/reset in the new records.
Existing bytes, algorithms and unknown original fields remain untouched. New field
formats/model metadata still need runtime qualification.

## Review, delivery and reopening

The exact profile, fresh native/source hashes, source geometry, pin-map evidence,
window roles, geometry hypothesis and append records participate in the proposal
digest. Changed evidence invalidates decisions. Every new part requires individual
review plus qualification-only acknowledgement. The complete native copy retains
all other archive payloads, member metadata, ordering, comments and distinct
Temp/backups. Those snapshots still contain original state and must not be substituted.
Insertion rollback must recover the original selected XML bytes exactly.

Profiles persist in the current project and in each new candidate's history snapshot;
older projects/history remain supported. Reopening verifies original source bytes and
recomputes proposals. Current evidence edits never rewrite historical evidence.
Fresh candidate parsing establishes preparation counts; accepted proposals alone do
not count. Constructed geometry is counted separately from full/partial template reuse.
Full component exports retain exact native identities, body/terminal roles and the
remaining binding/teaching work. Saved sources remain the originals; candidate bytes
remain in the separately delivered folder/archive.

## Qualification still required

On the exact Eagle version, compare an original control save with candidate
open/save/reopen. Verify each new placement/Master identity, body dimensions, native
units, origin and angle, local terminal rectangle axes, model metadata and window
properties. Verify that binding, teaching and any model synchronization preserve
the initial positions; this is unverified until measured. Assign pads only after
native WND_PAD coordinate/group/common-list semantics are established, assign FOVs
and teach image-dependent presence/lead/solder/other intended inspections. Review
physical alignment and populated applicability before enabling. Machine-specific
inspection validation and RCP release are separate. No scan-free job generation,
automatic alignment repair, taught inspection or machine/shared-library write is
claimed by this route.
