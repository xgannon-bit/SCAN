# Connected offline preparation and repair

Use Source intake to select a copied native archive, an explicit main/Temp/backup
pair and the available placement, layout, Gerber and BOM inputs. Save project
retains original bytes, mappings, constructor profiles and review history. Reopen
verifies hashes and rebuilds the analyses; it never trusts a saved transform or
report as current authority. Generated candidates retain their own archive bytes
and snapshot selection separately from the original and any Eagle-returned job.
Export reparses the actual candidate; reopening reparses it again and reproduces
the reviewed recipes against the original. The component work view verifies
created placement/Master/window identities, disabled state and absent algorithms
before reporting preparation. It shows every intended reference, partial models,
BOM-to-PCB/native identity differences and remaining machine actions.

In Board workspace, Reviewed source alignment compares explicitly selected
source scopes. It keeps revisions and origins distinct, uses a proper rigid
transform without fitted scale or reflection, and requires noncollinear fit
references plus independent check references. Unmatched identities, local
outliers and ambiguous correspondence hold the whole-scope derivative. A native
CAD comparison remains a numeric hypothesis while native units and frame
semantics are unqualified. No unregistered board image supplies evidence.

Component origin review adds source-owned pads, independent package/body
evidence and explicit output-anchor conventions to that shared transform. It
never fits component-specific offsets or treats a land midpoint as a proved body
center. Unknown physical side remains held. Reviewed centroid CSV export is a
separate source derivative with source-bound decisions, explicit exclusions and
round-trip validation; it is not native repair or qualified Eagle interchange.
See [origin review](origin-resolver.md) for evidence and serialization contracts.

In Repair Review, duplicate pairs expose placement geometry, exact model/window
and algorithm differences, binding literals and shared usage. The saved outcome
is a digest-bound comparison decision. A survivor preference does not suppress
an inspection. Unknown teaching or physical redundancy remains an explicit hold.

Supported native preparations remain individually reviewed disabled models.
Review a scalar experiment separately, including the exact identity, before/after
native ROI and dependent objects. Both export entry points combine the current
accepted preparations and scalar changes into one complete copy. Stale accepted
work blocks composition instead of silently disappearing. The writer rederives
both sets against original bytes, preserves unrelated records/assets, and checks
scalar rollback against the prepared baseline. The resulting work queue is
rebuilt from the final candidate.

## Starter limitation

Template reuse needs a suitable model in the selected job. Fresh package
construction currently also needs a placement, Master and suitable windows as
native field-format seeds. A genuine scanned starter with only scan, fiducials
and board color has not been qualified. Synthetic stripped-job tests prove that
missing seeds stay held; they do not establish real starter compatibility.
The append writer now supports validated explicit and self-closing empty
collections with exact rollback and preservation. This is a serialization
capability, not a universal seed or teaching default. Review lists exact missing
structural seeds and selected-profile requirements. Source review continues
independently of these native holds; see [starter requirements](native-starter-requirements.md).

## Qualification and next repair milestone

Geometry preparation and exact byte preservation are offline results. Native
binding serialization, FOV membership, runtime local-window propagation,
image-dependent teaching and position retention through Eagle open/save/reopen
remain unqualified. Temp/backup snapshots deliberately preserve their original
state. Development-test acceptance is distinct from operator approval, machine
validation and release.

The next repair milestone is an evidence-backed native coordinate and dependency
adapter: establish the exact CAD/module/ROI/Master/window contracts, diagnose
local origins separately from global registration, and review each dependent
change as one coherent set. Original duplicate, alignment and local-window issues
remain unfinished unless an exact change receipt explicitly includes them.
Qualifying source-owned binding intents into native artwork IDs and binding/FOV
records remains a separate contract. No nearest-pad association or automatic
enabling substitutes for that evidence.
