# Data policy

Public repository: source code, generic documentation and wholly synthetic tests only.

Private outside repository: employer/customer source designs, placement lists, job XML and archives, scans/photos, approved BOMs, device mappings, inspection results, detailed regression oracles, credentials and local runtime data. Do not expose these in exception output, hosted build logs, screenshots or issue attachments.

Do not publish or mirror another private repository to obtain its theme. Newly authored UI using a generic shared design language is distinct from copying application implementation, demo data or assets. Preserve required third-party licensing and notices when approved dependencies are later added. The owner has not selected a project license.

Ignore rules do not protect previously tracked or force-added files and cannot recognize every derived confidential fact. Review every staged diff before publication. Keep private tests local and authorized. A public source repository is compatible with a local-only runtime but does not itself provide runtime confidentiality.

Real inputs must not be sent to hosted inference without separate authorization. Deterministic local parsers and geometry rules own coordinates, repair eligibility and hashes. An optional explanation layer must not bypass validation or create missing geometry.
